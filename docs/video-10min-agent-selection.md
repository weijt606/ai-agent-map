# 十分钟讲清「怎么给自己挑一个 agent」

面向线上听众的口播稿，全长 600 秒，八段。配套导览页把同一套流程做成了可交互的选型器。

数据口径截至 2026-09-06。录之前对一遍：`agents/README.md` 的路线数、`capabilities/matrix.md` 的行数、`comparisons/cost-and-benchmarks.md` 的价格。数字变了就改稿，别在镜头前含糊过去。

## 录之前

浏览器开三个页签：仓库首页、能力矩阵、成本与基准。首页那张 `route-map` 图先滚到可见位置，第二段要切过去。

三句不能说的话：

不要说「最好的 agent 是 X」，整支片子的论点正好相反。不要把榜单增量说成「最受欢迎」，那是 7 天增量不是存量，说错了会被第六段自己打脸。厂商自测的 benchmark 一律带一句「这是厂商自己的数字」。

## 01 · 00:00-00:45 · 先把问题换掉

上屏：「哪个 agent 最好？」划掉，换成「我这件事该走哪条路线？」

> 你打开任何一份 agent 清单，第一反应大概都是：哪个最好？
>
> 这个问题没有答案。不是因为不好比，是因为今天叫 agent 的东西至少有五种完全不同的形态：终端里的编码 CLI、你自己拥有的循环、一整套自建框架、桌面上替你处理文档的助手，还有底下那层模型本身。把它们塞进同一个排行榜，本身就是个类别错误。
>
> 所以接下来十分钟，我不给推荐名单，给一个流程。四步，跟着走完，候选会从七十七个收敛到两三个。

这一段不出现任何产品名。一报名字，观众立刻掉回排行榜心态。

## 02 · 00:45-02:15 · 第一步：先选决策，再选产品

上屏：首页那张路线图，四类决策 + 15 条路线。

> 第一层只有四个选项，先在心里选一个。
>
> 第一，让 agent 直接上手你的代码，你要的是能改仓库的工具。第二，自己掌控循环，你不想继承别人产品的主张，要能改 agent 的那个 loop。第三，自建，你在做的是平台不是工具。第四，你其实是在选模型和技能层，不是在选产品。
>
> 这四类底下是十五条路线。关键在这儿：这一步不比好坏，只比「是不是同一类东西」。选完，七十七个候选大概只剩十几个。

停在图上说完再滚动。可以顺口提一句这张图是脚本生成的，条目数会自己对账。

## 03 · 02:15-03:45 · 第二步：圈出必需的那几列

上屏：能力矩阵，滚到 harness 那一节，让人看见 `● ◐ ○ —` 的密度。

> 选定路线之后，第二步是打开能力矩阵，圈出你的必需列。
>
> 一共九个维度：工具使用、代码执行、记忆、编排、多 agent、人工审批、调度、交互面、部署控制。
>
> 我要专门说三个，因为它们最常被跳过。人工审批，这个 agent 动手之前会不会停下来问你。交互面，它只活在终端里，还是能进 IDE、进 CI、进你的聊天工具。部署控制，你能不能自己托管、能不能读它的源码。
>
> 诀窍只有一句：圈「没有就不行」的列，别圈「听起来不错」的列。选错的人，通常是被一个自己根本用不上的强项吸引了。

别逐个念九个维度，念到第三个就够了。

## 04 · 03:45-04:55 · 第三步之一：闸门在谁手里

上屏：闭源与开放权重的对照。

> 第三步是三个真正拉开差距的轴，第一个是治理。
>
> 看这组对照，它们发生在同一个时间窗里。左边，OpenAI 的 GPT-6 Astra，面向公众的那个版本会直接拒答一部分网络安全类的问题，更强的能力要过审批。Anthropic 也一样，能力更放开的那一档只对经审核的机构开放。
>
> 右边，智谱的 GLM-5.3，在漏洞发现的 benchmark 上是开源最强，而它是 Apache-2.0、权重直接下载。
>
> 我不评判哪种对。但选型上的后果是具体的：在开放权重这一档，那道闸门是你的政策，不是厂商替你把的。它意味着你 harness 里的审批设计，正在替你做闭源厂商本来会做的那部分工作。

全片信息密度最高的一段，语速放慢。「我不评判哪种对」这句一定要说，两边论据都成立，选边站会招来不必要的争论。

## 05 · 04:55-05:45 · 第三步之二：默认值会在你脚下改掉

上屏：Codex 两个版本号和 release note 原文。

> 第二个轴更隐蔽：默认值会变，而且是在补丁版本里变。
>
> 九月三号和四号，Codex 的命令行工具连发两个版本。第一个加入了对新模型 Astra 的支持，第二个按它自己 release note 的原话，把 Astra 设成了「未显式配置模型时打包的默认」。
>
> 把这个和上一页连起来看：那个会拒答部分网安问题的受限版本，现在是一个编码产品的静默默认值。而绝大多数人不会去读 release note。
>
> 所以这条要变成习惯：你依赖的工具，它的默认模型是什么，定期回头确认一次。

这页短，别拖。可以顺手说一句，这就是为什么这张地图去读 release note 而不是读新闻稿。

## 06 · 05:45-07:15 · 模型层是一个独立决策

上屏：四行价格表。

> 第三个轴，也是很多人没意识到自己在做的一个决策：模型层要单独选。
>
> 看这张表。九月一号和三号，两家的旗舰前后脚更新，然后落到了完全相同的标价，都是每百万 token 十美元进、五十美元出。
>
> 标价一样，那比什么？比两件事。第一是缓存读，一边两毛五，一边一块。长会话的 agent 每一轮都在重放一大块上下文，账单其实堆在这一列，不在标价那一列。第二是长上下文的计价形状，一边整个窗口都是标准价，另一边超过二十七万二千 token 之后整个请求换价。一个长会话，可能没人拍板就越过了那条线。
>
> 而更实际的是下面两行：大多数活其实该跑在便宜的档上。同一家内部，最贵和最便宜差五倍。

强调「账单堆在缓存读那一列」，这是多数人没算过的账。开放权重档一句带过，别展开。

## 07 · 07:15-08:20 · 热度不等于适合

上屏：四个项目的回吐幅度。

> 最后一个坑，跟排行榜有关。
>
> 这张地图每周三刷一次七天增量榜。它给自己定了一条规矩：单个窗口只是尖峰，要等第二个窗口确认才算趋势。
>
> 这条规矩已经连续兑现四次了。这四个项目，每一个在上一个窗口都是「本榜有记录以来最猛的一次加速」，然后下一个窗口分别还回去了 59%、64%、57%、73%。最后那个尤其说明问题，它上一期是第一名，这一期掉到第六。
>
> 所以：榜是用来发现新项目的，不是用来选型的。你在热搜上看到的那个，很可能只是它这辈子最亮的那一周。

四个条形讲完再指，别一上来就念数字。「它上一期是第一名」这句要停顿。

## 08 · 08:20-10:00 · 收尾

上屏：三步 + 三个入口。

> 收个尾。整个流程就三步：路线表收敛范围，能力矩阵圈必需列，成本与基准把模型层单独算一遍账。
>
> 如果只带走一个动作，我建议是这个：把你现在正在用的那个 agent，按刚才那九个维度圈一遍。不是去找新的，是先搞清楚手上这个，在你真正需要的那几列上到底是不是强项。我自己做这件事的时候，发现有两列一直是空的，而那两列恰恰是我每天在手动补的。
>
> 这张地图是开源的，中英双语，每周三刷一次榜。它的立场很简单：它不告诉你该选什么，它告诉你你到底在选什么。
>
> 链接在下面。有你觉得该收录的项目，欢迎提 issue。

「我自己做这件事的时候」那句必须换成你真实的经历，否则整段的可信度就塌了。最后报一次仓库名，字幕里也放一次。别念 star 数收尾。
