一句话：WorkBuddy 是腾讯的桌面办公 agent——本地图为代码追踪的那套"给它一个目标，它自己驱动你的文件和应用"的模式，换到文档、表格和幻灯片上；到 2026 年年中，它已是中国同类产品里流量最高的一个。

## 一眼判断

| 项目 | 结论 |
| --- | --- |
| 厂商 | 腾讯（出自 CodeBuddy 一系） |
| 路线 | 通用自主 agent——面向办公与知识工作，而不是代码仓库 |
| 是否开源 | 否 |
| 最适合 | agent 能端到端做完的非工程工作：报告、幻灯片、表格、调研 |
| 主要代价 | 按 credit 计费的商业产品；闭源，且要读写你的本地文件 |
| 使用面 | 桌面客户端（Windows / macOS）、网页版、微信小程序、企业入口 |
| 官网 | https://copilot.tencent.com/work/ |

## 为什么要收录

本地图以重心而非规则来说是一张编码 agent 地图——它已经收了做个人数据生活整合的 [OpenHuman](openhuman.md) 和做工作流自动化的 [n8n](n8n.md)。收录 WorkBuddy 的理由更窄：它是最清楚的证据，说明**本地图记录的这套 agent 模式已经跑出了代码仓库**，而且第一次成规模地跑出去是在中国。

腾讯把它定位成覆盖日常办公、代码开发与创意设计的全场景 AI 办公工作台——一个会理解、拆解并执行的智能同事，而不是只给建议。放回本目录里读，这个循环很眼熟：自然语言目标、自主拆解、工具调用、自我校验、一个你可以验收或打回的交付物。变的只是工具。

## 什么时候选它

- 工作是**办公形态**的：Word、Excel、PPT、PDF、图片——读写、合并、转换——而且你要的是成品而不是建议。
- 你想要**多 agent 并行**处理一个项目，又不想自己搭一套 harness。
- 你想要**预置的领域角色**。腾讯提供 100+ 个专家角色，覆盖招聘、调研、前端、法务、营销等方向。
- 你需要它在你合上笔记本之后继续干：云端托管任务 7×24 运行，还能通过腾讯自家的消息入口用手机指挥。
- 你本来就在中国企业协作栈里——企业微信、QQ、飞书、钉钉的绑定正是它设计的运行环境。

## 什么时候不选它

- **你是在选编码 agent。** 面向仓库的活，本地图上其他任何条目都是更好的起点——包括腾讯自己那个本地图尚未收录的 CodeBuddy。
- **你在意能不能读懂它做了什么。** 闭源、且带授权访问本地文件运行，和这里那些开源 harness 是本质不同的治理位置。这是实打实的取舍，不是形式问题——日志不归你的时候会失去什么，见[观测与评估](../comparisons/observability-and-evals.md)。
- 你要在中国大陆平台之外用它。集成、模型选择和支持都是为那个市场建的。
- 你需要模型透明：产品界面允许在多个大模型之间切换，但某一步具体由谁执行，产品页并没有钉死。

## 能力形状

| 维度 | 判断 | 说明 |
| --- | --- | --- |
| 办公成品生成 | 很强 | 产品的核心主张：可直接验收的文档、表格与幻灯片 |
| 任务拆解 | 强 | 自主多步规划并自我校验 |
| 多 agent | 强 | 多个 agent 并行处理同一项目 |
| 本地文件操作 | 强 | 在你授权的目录内读写 |
| 远程 / 移动控制 | 强 | 通过企业微信、QQ、飞书或钉钉绑定；手机端操控桌面 |
| 模型选择 | 中 | 可切换多个大模型；但与步骤的对应关系未公布 |
| 开源 / 可审计性 | 无 | 闭源 |

## 市场位置

2026 年 6 月，也就是 3 月 9 日发布约三个月后，WorkBuddy 被报告达到 **2,097 万月访问量——超过第二名与第三名之和**，而整个中国桌面 AI 办公品类 17 款被跟踪产品合计超过 6,000 万。阿里在 7 月把自己三个 agent 产品整合成一个办公产品，字节则把豆包推进同一战场。这些是二手市场数据，本地图按趋势记录，而不是当作厂商核实过的数字。

选型上的要点不是流量，而是：**办公 agent 现在已经是一个厂商在正面争夺的独立品类**，跑着同一套循环，却完全没有本地图编码那一侧习以为常的开放性。

## 结论

WorkBuddy 在这里的位置是边界样本：循环本地图认得，产品面本地图通常不覆盖，而它的治理故事恰好是旁边那些开源 harness 的反面。如果活是文档、而且你在它的生态里，就选它。如果你事后会想审计它对你的文件做了什么，就别选。
